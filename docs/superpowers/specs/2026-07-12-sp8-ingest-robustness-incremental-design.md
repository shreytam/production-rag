# SP8 · Ingest Robustness & Incremental Updates — Design Spec

**Date:** 2026-07-12
**Status:** DRAFT — pending user review (design decisions are PROPOSED, not yet approved)
**Program:** Production-hardening, Phase 2. Hardens the ingest write-path and adds content-hash incremental re-embedding. Depends on SP1 (tenancy: the manifest and every new store method are tenant-scoped) and the VectorStore Protocol landed in Wave 1. Explicitly does **not** decide physical per-tenant isolation (VDB-Decision / SP11) — it works with the current pooled-filter model.

---

## 1. Context & problem

Verified against the current code (line numbers confirmed by reading the files):

| # | Defect | Location | Impact |
|---|---|---|---|
| D1 | Contextual prefixing has **no per-chunk error isolation**: one LLM error or a `KeyError` on the cache `data["prefix"]` raises out of `annotate`'s loop and aborts the **entire** ingest run. | `ingest/contextual.py:127-134` (loop), `:104` (LLM call), `:92-93` (cache read) | First transient 500 or corrupt cache file loses the whole run. |
| D2 | **Non-atomic cache write**: `cache_file.write_text(...)` is a single non-atomic call. A crash/`SIGKILL` mid-write leaves a truncated JSON file that is treated as a valid hit forever (`json.loads` either raises — see D1 — or returns garbage). | `ingest/contextual.py:107-110` write; `:91-93` read | Permanently poisoned cache entries; no self-heal. |
| D3 | **Full document sent per chunk**: `_USER_TEMPLATE.format(doc_text=doc_text, ...)` embeds the entire doc in every per-chunk call → O(doc_len × n_chunks) tokens. `context_token_budget` (config) is **never** referenced in this file. | `ingest/contextual.py:99-102`; `grep context_token_budget ingest/` → 0 hits | Cost blows up on long docs; rate-limit / timeout risk. |
| D4 | **Cache key omits doc context and prompt version**: `_cache_key(doc_id, chunk_text)` = `sha256(doc_id + chunk_text)`. Two different documents that happen to share a `doc_id` collide; and any edit to `_SYSTEM_PROMPT`/`_USER_TEMPLATE` silently serves **stale** prefixes generated by the old prompt. | `ingest/contextual.py:50-52` | Stale/incorrect prefixes survive prompt changes; weak dedup. |
| D5 | **No idempotency / checkpointing / batching** in the run driver: it chunks → embeds **all** texts in one call → upserts **all** at once. A failure anywhere after line 79 loses every embedding computed so far; a re-run re-embeds everything from scratch. | `ingest/run.py:77-88` | Mid-run failure = total rework; expensive re-embeds on every run. |
| D6 | **No orphan deletion / no incremental path.** The `VectorStore` Protocol exposes only `ensure_collection / upsert / search / count` — **no `delete`, no metadata-only update**. When a doc shrinks (10→8 chunks), stale `::000008/::000009` points linger forever; and there is no way to re-write payload (title/acl) without re-embedding. Re-ingest re-embeds **every** chunk even when unchanged. | `core/interfaces.py:40-49`; `providers/vectorstores/qdrant_store.py:95-109`; `providers/vectorstores/pgvector_store.py:84-125` | Orphaned vectors leak into results; every re-ingest pays the full embed bill. |

**What is already correct (do not "fix"):** chunk IDs are already deterministic — `f"{doc.doc_id}::{ordinal:06d}"` (`ingest/chunking.py:151`) — and both stores key on it (Qdrant `uuid5(chunk_id)` at `qdrant_store.py:24,103`; pgvector `PRIMARY KEY (chunk_id)` + `ON CONFLICT` at `pgvector_store.py:60,99`). Re-ingesting **identical** content already upserts in place, it does **not** duplicate. The real gaps are D6 (orphans + metadata-only path) and the fact that ordinals are **positional**: inserting a paragraph at the top of a doc shifts every downstream ordinal and busts the manifest diff (§4 D-ID).

## 2. Goals

- **G1 — Per-chunk fault isolation.** A single chunk's LLM/parse failure skips *that chunk* (embed it without a prefix) and never aborts the run.
- **G2 — Atomic, self-healing caches.** Both the contextual cache and the manifest use temp-file + `os.replace` atomic writes; a corrupt/unreadable entry is treated as a **miss** (recomputed), never as a poisoned hit.
- **G3 — Bounded contextual cost.** Truncate `doc_text` to a dedicated ingest budget before templating; the cache key includes the (truncated) doc context digest **and** a prompt-version tag, so stale prefixes are impossible after a prompt/template change.
- **G4 — Idempotent, resumable, batched writes.** Embed → upsert → **then** record — in tenant-scoped batches, so a mid-run failure resumes exactly where it stopped with no double work and no lost work.
- **G5 — Content-hash incremental re-ingest (Notion pattern).** A per-doc manifest holds each chunk's embed-input hash + metadata hash. On re-ingest: re-embed **only** chunks whose embed hash changed; `set_payload`/`UPDATE` **only** chunks whose metadata hash changed; **delete** chunks that vanished; skip everything unchanged.
- **G6 — Extend the store contract cleanly.** Add `delete` and `update_metadata` to the `VectorStore` Protocol and both impls (Qdrant, pgvector), tenant-scoped and fail-closed, wired only through the existing registry pattern.

## 3. Non-goals (deferred) — owner named

- **Chunker trailing-overlap / positional-ordinal correctness bug** → **SP4** (Chunking). SP8 consumes chunk IDs as produced; it does not change the chunking algorithm. (SP8 only *records honestly* that positional ordinals cause over-re-embedding on insertions — §4 D-ID.)
- **Physical per-tenant isolation / namespace-per-tenant / vector-DB choice** → **VDB-Decision / SP11**. The manifest and all new store methods work against the current pooled-filter model; the manifest key is `(tenant_id, doc_id)` so it survives a later migration to physical namespaces unchanged.
- **Auth / identity derivation** → **SP1**. SP8 assumes documents already carry a trustworthy `tenant_id` (set at load time) and scopes every store write/delete by it.
- **BM25 incremental indexing** → deferred (see §6). SP8 rebuilds BM25 in full each run (cheap, local, `rank-bm25` in-memory + pickle). Incremental sparse indexing is a future hook, not this slice.
- **Rate limiting / global retry policy for the embedder** → **SP6** (Resilience). SP8 batches and checkpoints; it relies on the embedder's own SDK retries.

## 4. Decisions (PROPOSED)

Lead option is the best-practice choice. All are **PROPOSED** — confirm/override on review.

| # | Decision | Choice (proposed) | Rationale |
|---|---|---|---|
| D-HASH | Hash function for manifest | **`hashlib.blake2b(digest_size=16)`** (stdlib, no new dep); `xxhash` a config-selectable option | Fast, collision-resistant enough for change-detection; keeps the slice dependency-free. |
| D-EMBEDHASH | What triggers a re-embed | Hash over **`chunk.embed_text`** (prefix + text), not raw `text` | The contextual prefix is part of the embedded string (`core/types.py:75-80`); hashing raw text would miss a regenerated prefix → stale vectors. |
| D-METAHASH | What triggers a metadata-only write | Separate hash over payload fields: `title, source, tenant_id, acl_tags, metadata, ordinal, doc_id` | `acl_tags`/`tenant_id`/title edits change the payload but **not** the vector → `set_payload`/`UPDATE`, never a re-embed. |
| D-CKPT | Checkpoint mechanism | **The manifest IS the checkpoint** — no separate checkpoint file | The manifest already tracks per-chunk durable state; resume = re-run, manifest skips done chunks. One source of truth. |
| D-ORDER | Write ordering | **embed → upsert store → THEN atomically write manifest** | Manifest must record only what is *durably in the store*. Manifest-first + crash = false "stored" claim → silent data loss. |
| D-ID | Chunk primary key | **Keep `doc_id::ordinal:06d`** as the physical PK; accept insertion-driven over-re-embed | Changing the PK is a store migration (out of scope). Content-addressed IDs (hash-in-ID) noted as a future hook (§11). |
| D-CORRUPT | Corrupt manifest / cache entry | **Treat as full miss** (recompute the doc / recompute the prefix), fail *safe* (slower, correct) | Same rule as the corrupt-cache-is-a-miss policy; never trust a partially-written record. |
| D-PROMPTV | Prompt versioning | `_PROMPT_VERSION` constant in `contextual.py` folded into the cache key | A template edit auto-invalidates every cached prefix without a manual cache wipe. |
| D-DOCCTX | Contextual doc budget | New dedicated `contextual_doc_token_budget` knob (NOT `context_token_budget`) | `context_token_budget` is the *query-time* assembly budget; overloading it conflates two unrelated limits. |
| D-STORE | Store interface for incremental | Add `delete(chunk_ids, acl)` + `update_metadata(chunk_id→payload, acl)` to the Protocol | Incremental re-ingest is impossible on the current 4-method surface (§1 D6). |
| D-MANSTORE | Manifest storage backend | **`JsonlManifestStore`** (one JSON file per `(tenant, doc_id)` under `manifest_dir`), behind a `ManifestStore` Protocol | Offline-testable, no infra; a DB-backed impl drops in later behind the same Protocol. |

## 5. Architecture & components

Follows the existing pattern: Protocols in `core/interfaces.py`, concrete impls in `providers/`, wired **only** in `core/registry.py`. Small single-purpose units.

### 5.1 `DocManifest` / `ChunkRecord` (types) — `core/types.py`
Plain Pydantic records (consistent with the other wire types):
```
class ChunkRecord(BaseModel):
    chunk_id: str
    ordinal: int
    embed_hash: str      # blake2b(embed_text)
    meta_hash: str       # blake2b(payload fields)

class DocManifest(BaseModel):
    tenant_id: str
    doc_id: str
    prompt_version: str          # the _PROMPT_VERSION active when built
    chunks: dict[str, ChunkRecord]   # chunk_id -> record
```

### 5.2 `ManifestStore` (Protocol) — `core/interfaces.py`
```
class ManifestStore(Protocol):
    def load(self, tenant_id: str, doc_id: str) -> DocManifest | None: ...   # None or corrupt → None (full re-ingest)
    def save(self, manifest: DocManifest) -> None: ...                       # atomic (temp + os.replace)
    def delete(self, tenant_id: str, doc_id: str) -> None: ...
```

### 5.3 `JsonlManifestStore` — `providers/manifest/jsonl_store.py`
- One file per doc: `manifest_dir/{tenant_id}/{sha of doc_id}.json`. `tenant_id` in the path *and* in the body (fail-closed cross-check on load).
- `load` returns `None` on missing / unreadable / JSON-invalid / tenant-mismatch (D-CORRUPT).
- `save` writes to `*.tmp` then `os.replace` (atomic on POSIX) (G2).

### 5.4 `VectorStore` Protocol extension — `core/interfaces.py` (+ both impls)
Add two methods (G6, security-critical — tenant-scoped, fail-closed):
```
def delete(self, chunk_ids: list[str], acl: ACLContext) -> None: ...
def update_metadata(self, updates: dict[str, dict], acl: ACLContext) -> None: ...  # chunk_id -> payload subset
```
- **Qdrant** (`qdrant_store.py`): `delete` → `client.delete` with a filter that is `must(id ∈ uuid5(chunk_ids))` **AND** `qdrant_filter(acl)` (tenant match); `update_metadata` → `client.set_payload` gated by the same ACL filter.
- **pgvector** (`pgvector_store.py`): `delete` → `DELETE ... WHERE chunk_id = ANY(%s) AND {pg_where(acl)}`; `update_metadata` → `UPDATE ... SET ... WHERE chunk_id = %s AND {pg_where(acl)}`. No embedding column touched.
- Both **fail closed**: the ACL predicate is always ANDed in, so a delete/update can never cross a tenant boundary even if a caller passes a foreign `chunk_id`.

### 5.5 `ContextualPrefixer` hardening — `ingest/contextual.py`
- `_PROMPT_VERSION = "v1"` constant (D-PROMPTV).
- New `_cache_key(doc_ctx_digest, chunk_text, prompt_version)` = `blake2b(prompt_version + doc_ctx_digest + chunk_text)` where `doc_ctx_digest = blake2b(truncated_doc_text)` (D4).
- `prefix_for` truncates `doc_text` to `contextual_doc_token_budget` tokens (reuse `ingest.chunking._get_encoder`) before templating (D3).
- Cache read: corrupt/unparseable file → treat as miss, recompute (G2/D2). Cache write: temp + `os.replace` (D2).
- `annotate`: wrap each chunk in `try/except`; on failure log `chunk_id` + reason and leave `contextual_prefix=None` (chunk still ingested, un-prefixed) (G1). Return `(annotated, skipped_ids)` so the driver can surface a count.

### 5.6 `IncrementalIngestor` — `ingest/incremental.py`
The heart of the slice. Depends only on Protocols (`Embedder`, `VectorStore`, `ManifestStore`). Per doc:
1. Chunk → annotate (contextual) → compute `embed_hash`/`meta_hash` per chunk.
2. Load prior `DocManifest`. If `None` or `prompt_version` changed → treat **all** chunks as new.
3. Diff:
   - `to_embed` = chunks whose `embed_hash` changed (or new).
   - `to_meta` = chunks unchanged in embed but changed in `meta_hash`.
   - `to_delete` = chunk_ids in the old manifest absent from the new set (orphans, incl. shrink tail).
4. Embed `to_embed` in batches of `embed_batch_size`; `upsert` them; `update_metadata` for `to_meta`; `delete(to_delete, acl)`.
5. **Then** atomically `save` the new `DocManifest` (D-ORDER).

### 5.7 Registry wiring — `core/registry.py`
`build_manifest_store(settings)` — the only place `JsonlManifestStore` is named. `IncrementalIngestor` is assembled from the existing `build_embedder` / `build_vector_store` / `build_manifest_store`.

### 5.8 Driver — `ingest/run.py`
`--incremental` flag routes docs through `IncrementalIngestor` instead of the bulk embed+upsert block (`run.py:77-88`). BM25 index + golden export unchanged (full rebuild each run — §6).

## 6. Data flow

```
Re-ingest one document (incremental path):

doc ──chunk_document──▶ chunks ──annotate(per-chunk, skip-on-error)──▶ chunks(+prefix?)
                                                    │
                         per chunk: embed_hash=blake2b(embed_text)
                                    meta_hash =blake2b(payload fields)
                                                    │
   load DocManifest(tenant,doc)  ◀─── JsonlManifestStore
        │  (None / corrupt / prompt_version changed  ⇒ all-new)
        ▼
   DIFF ─┬─ to_embed  (embed_hash changed/new) ─▶ Embedder.embed_documents (batched)
         │                                          └▶ VectorStore.upsert
         ├─ to_meta   (meta_hash changed only)  ─▶ VectorStore.update_metadata  (no re-embed)
         ├─ to_delete (in old, gone now)        ─▶ VectorStore.delete(ids, acl)  (orphans)
         └─ unchanged                            ─▶ (skip)
                                                    │
                        ── ALL store writes durable ──▶ ManifestStore.save (atomic)   ◀ D-ORDER
```
BM25 stays a **full rebuild**: `sparse.index(all_chunks)` + pickle each run (`run.py:91-98`), independent of the incremental dense path. This is intentional and cheap (in-memory `rank-bm25`); incremental sparse is a §11 future hook. §6's diff applies to the dense store + manifest only.

Crash safety: because manifest `save` happens **after** every store write is durable, a crash leaves the manifest describing a strict subset of what's stored. On resume the re-run re-diffs; already-stored chunks whose hashes match are skipped, un-recorded chunks are re-embedded (safe redo, never a silent skip).

## 8. Error handling — explicit; security paths fail closed

- **Per-chunk contextual failure (G1):** LLM error, timeout, or empty/oversized response → caught in `annotate`; log `chunk_id` + reason code; `contextual_prefix=None`; chunk continues to embed/upsert. A run-level counter of skipped chunks is printed; the run does **not** abort.
- **Corrupt contextual cache (D2/G2):** unreadable / non-JSON / missing `prefix` key → treated as a miss, recomputed, re-written atomically. Never raises.
- **Corrupt / missing / tenant-mismatched manifest (D-CORRUPT):** `load` returns `None` → the doc is fully re-ingested (all chunks re-embedded). Fail **safe** (correct-but-slower), never trust a partial record.
- **Atomic writes (G2):** contextual cache and manifest both write `*.tmp` + `os.replace`. A crash mid-write leaves the previous good file intact (or none), never a truncated "valid" file.
- **Store delete/update ACL (security-critical, fail closed):** `delete` and `update_metadata` **always** AND the caller's `acl` (tenant + tags) into the store predicate. A caller passing a chunk_id belonging to another tenant deletes/updates **nothing** — no cross-tenant mutation is expressible. Mirrors the existing read-path guarantee (`qdrant_filter`/`pg_where`).
- **Embedder batch failure (D5):** a batch that fails after `max_retries` aborts the run with the manifest reflecting only durably-stored batches; a re-run resumes from the first un-recorded chunk (no re-embed of recorded ones, no lost work).
- **Empty embedding / dimension mismatch:** the existing `upsert` guard (`chunk.embedding is None → ValueError`) is preserved; the incremental path never sends a chunk to `upsert` without an embedding.

## 9. Testing (TDD) — concrete, offline-testable

All offline (fake `Generator`/`Embedder`, in-memory or ephemeral fake vector store, `tmp_path` for caches/manifest). Red first.

**Contextual hardening**
1. One chunk's `generator.complete` raises → `annotate` returns the other chunks annotated, the failing chunk has `contextual_prefix=None`, run does not raise; skipped-count == 1.
2. A truncated/garbage cache file → treated as a miss (generator is called again), then an atomic rewrite yields a valid file.
3. `doc_text` longer than `contextual_doc_token_budget` → the templated user message is truncated (assert token count ≤ budget); prefix still produced.
4. Bumping `_PROMPT_VERSION` changes the cache key → a previously-cached prefix is **not** served (generator re-invoked).
5. Same `doc_id` but different `doc_text` → different cache key (no collision, D4).

**Manifest & diff**
6. First ingest of a doc → all chunks in `to_embed`, none in `to_meta`/`to_delete`; manifest written.
7. Re-ingest identical doc → `to_embed`/`to_meta`/`to_delete` all empty; embedder call-count unchanged (skip works).
8. Edit one chunk's text → exactly that chunk re-embedded (embed_hash changed); others skipped.
9. Change only `acl_tags`/`title` (metadata) → that chunk in `to_meta` only; `update_metadata` called, embedder **not** called for it.
10. Doc shrinks 5→3 chunks → the 2 dropped chunk_ids are in `to_delete`; `store.delete` called with exactly them.
11. Corrupt manifest file → `load` returns `None` → full re-ingest (all chunks embedded).
12. Tenant-mismatched manifest body vs path → `load` returns `None` (fail-closed).

**Store methods (ACL fail-closed)** — exercise real `qdrant_filter`/`pg_where` predicates against an ephemeral store, coordinated with SP5 CI:
13. `delete([foreign_chunk_id], acl=tenant_A)` where the chunk is tenant_B → row still present (no cross-tenant delete).
14. `update_metadata` for a foreign-tenant chunk → payload unchanged.
15. `delete` of an in-tenant chunk → gone; `count(acl)` drops by one.

**Crash / ordering (D-ORDER)**
16. Simulate a crash after `upsert` but before `manifest.save` (inject a raise) → re-run re-embeds the un-recorded chunks and completes; no chunk silently missing from the store.

## 11. Open questions / future hooks

- **Content-addressed chunk IDs** (hash-in-ID instead of positional `ordinal`) would make paragraph insertions cheap (no downstream ordinal shift → no over-re-embed). It's a store-migration (new PK) — deferred; the manifest is designed so this can be swapped in later without changing the diff logic.
- **Incremental BM25.** SP8 rebuilds the sparse index in full each run. A per-doc incremental sparse index (delete + add postings) is a future hook once the corpus outgrows an in-memory rebuild.
- **DB-backed `ManifestStore`.** The JSONL impl is offline-first; a Postgres/Redis impl behind the same Protocol removes the per-doc file fan-out at scale.
- **Manifest ↔ VDB-Decision.** The manifest key is `(tenant_id, doc_id)` today. If SP11 moves to physical namespace-per-tenant, the manifest partitions cleanly by tenant with no schema change — confirm the key shape survives that migration when VDB-Decision lands.
- **Prompt-version migration policy.** Bumping `_PROMPT_VERSION` invalidates *all* cached prefixes and re-embeds the whole corpus on next incremental run. Decide whether that should be a gated/opt-in migration rather than automatic on flag flip.
- **`xxhash` as default.** If profiling shows blake2b hashing is a bottleneck at corpus scale, promote `xxhash` from option to default (adds a dependency).
